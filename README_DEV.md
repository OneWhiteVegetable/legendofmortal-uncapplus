# UncapSixStats — 活侠传六维/武功上限解除 Mod

取消《活侠传》(Legend of Mortal) 六维(體力/內力/輕功/拳掌/刀劍/暗器)及全部武功类属性
(腿法/奇門/軟兵器/槍棍/內功)的 100 点上限,修炼不再封顶,想练什么就练什么。

v2.0.0 新增:**更好的天命点分配**(继承界面重做,面板开关「更好的天命點分配(繼承介面)」,默认开):

- **加点立即落实**:点一下就是加好了,不再有"未确认"中间态;也因此可以随便切
  属性/人际/门派三页对照着点,原版"本页有已分配的点数尚未确定"拦截弹窗彻底消失。
- **每项都有减号**(性格本来就有):只退你刚分配的点数,初始值减不动;
  没有分配过时减号不出现,分配了才出现,给你一个收回想法的途径。
- **性格费用正常了**:性情/處世/道德/修養按"偏离初始值"计费——远离中立扣点,
  点回中立退点,来回一趟 0 消耗(原版来回白扣 2 点)。
- **复原 = 回到最初**:三页全部回到打开继承界面时的状态,本次点数全退(原版只退回上次确定)。
- **确定 = 结束加点**:直接关闭继承界面进入下一环节(和右上角 X 一样);
  如果还有点数没分配完,会弹窗告诉你**剩余点数会转成命运点带进游戏**,
  弹窗是克隆游戏自带弹窗做的,风格一致;勾上「之後不再提示」以后多周目不再弹
  (存在 mod 配置里,不写存档)。
- **加点破限变色**:六维(配合上限解除)、武學點數/銀兩/鍛造/煉丹的点数上限也放开了。
  数值在原设计上限内是蓝色,**突破原上限后变金色**,一眼分清哪些点过了头;
  进度条照常不溢出。
- **长按连点**:按住 + / − 不放就连续加/减,不用一下一下戳。
- **点数守恒承诺**:mod 全程只通过游戏自身的加点机制 ±1 变动天命点池,
  每次变动都在 `BepInEx/LogOutput.log` 留 `[天命]` 审计行,随时可以自己对账;
  复原/减点严格退费,绝不私自增减。

面板 UI 同步优化:右上角改成 **×** 关闭;三个 mod 开关(上限解除/肌肉立绘/天命分配)
和其余开关统一换成**滑条**(金色在右=开,灰色在左=关),一眼可读。
配套小修:银两超过 99999(原上限,正好五位)后,各处钱数显示自动缩字,
六位、七位也完整显示(商店/HUD 通用,只动显示不动数值)。

v1.9.2 新增:**肌肉立绘联动**(素材来自韩国玩家的 giga_player 立绘包,已整合进安装包)。
面板开关「趙活:你在唐門只能算是個蘿莉」打开后,任一六维(體力/內力/輕功/刀劍/暗器/拳掌)

## 打开 Mod 面板(**读档或新游戏进入游戏后**才有入口,标题界面没有)

1. **鼠标:点右上角齿轮「系統」打开系统菜单,里面「環境設定」右边多了个「上限解除」按钮**——
   它是直接克隆游戏自己的按钮注入的,背景/字体/悬停效果与游戏完全一致;
2. 键盘:按 **F2**(笔记本友好)直接开关面板。

注意:**F11 是游戏自带的"隐藏界面"功能**,与 mod 无关;误按导致菜单消失时再按一次 F11 恢复。

面板内容(所有设置即时生效并自动保存):总开关、雷达图破限特效(顶出距离/视觉上限/
浓度/流动/颜色预设)、曲线延伸开关与倍率、六维 ±10 调试按钮(真实数值,改错用 −10 还原
再存档)、诊断按钮。

## 技术备忘(面板为什么折腾了几版 —— 根因已由自检日志实锤)

这个游戏有一个罕见怪癖:**引导场景(CoreScenes)切换时会销毁外来物体**——
BepInEx 插件宿主物体和插件 Awake 期创建的 GameObject 全部被杀
(自检:`Plugin 组件存活: False` / `Awake 标记物体存活: False`),
导致插件宿主上的 Update/OnGUI 永远不会执行;标题场景还没有 EventSystem。
v1.5.x 只用"已被实测证实可行"的机制:

- 面板创建时机推迟到**读档/新游戏时**(挂在 GameStat.SetValue/Reset 的一次性 postfix 上,
  这两个方法游戏自己一定会调,且此时场景已稳定);
- 入口按钮**注入游戏自带的系统菜单**(克隆「環境設定」按钮,清空原事件后改字;
  位置在菜单打开两帧后按源按钮最宽子元素(悬停红幅)的实际宽度恰好相挨,与分辨率无关);
  系统菜单关闭(CommonPanel.Show(false))时联动关闭 Mod 面板;
  面板文案全部使用繁体中文,匹配游戏字体(简体字会回退成黑体,风格不统一);
- 交互用标准 uGUI Button + 游戏内 EventSystem;
- 热键(F2/F10/F9)由后台线程 Win32 轮询,与 Unity 消息循环完全解耦;
  前台判定用"前台窗口线程 PID == 游戏 PID"(Mono 下 MainWindowHandle 不可靠);
  需要碰 Unity 对象的操作经 UnitySynchronizationContext 投递到主线程;
- 首次创建面板时写入全量环境自检日志。

## 原理(为什么这样改不会"隐形变弱")

游戏的上限来自 `GameStat._max`(默认 100),加点时被 clamp。但 `_max` 同时被曲线转换
(`CurveStatConvertData` 用 `InverseLerp(min, max, value)` 归一化)、等级文字、进度条、
雷达图分母引用——直接改大 `_max` 会让同样的 90 点从"90%"稀释成"9%",反而变弱。

本 mod 的做法是 **`Max` 保持 100 不动,只放开数值本身的钳制**:

- 90 点永远等于 90%,曲线/等级/进度条行为与原版完全一致,绝无稀释;
- 战斗中的伤害转换全是线性的(数值 × 转换率),100→500 伤害照常线性增长,没有 S 型曲线;
- 曲线类加成(如部分血量/加成)原版在 100 处饱和;由补丁 8 按曲线尾部斜率继续外推,
  破限后递增但递减,努力永不白费(可在面板关闭,恢复"100 处饱和")。

这是继承界面破限加点能带进游戏的前提;关掉天命分配开关即恢复原版钳制。)

## 雷达图"破限层"视觉设计

- 原六边形(白色实心)只画到 100%,保持原版观感;
- 破限层是三层亮银色调(银灰/亮银/荧光银白)的多边形克隆,**垫到面板最底层**
  (背景之上、白色六边形和文字之下),顶得再远也遮不住任何文字或 UI;
- **顶点位置固定不动**;荧光闪闪的流动感来自三层相位错开的尖峰闪光波
  (快速亮起、缓慢熄灭,此起彼伏),叠一层高频微颤模拟星点;
- 超出部分按对数压缩:200→1.3 倍、500→1.7 倍、1000→2 倍半径,十倍才翻一倍,不霸屏;
- 无破限时三层完全隐藏。
